# Zendesk BDR manager pipeline review

Read [the manager contract](../../references/shared/zendesk-manager-inspection-contract.md), [the evidence/process contract](../../references/shared/zendesk-evidence-and-process.md), and [the tool-access contract](../../references/shared/seller-tool-access-contract.md).

Core evidence is the exact team/rep and period, opportunity/account IDs, source definitions, Stage 0/1 state, meeting outcomes, ownership, and as-of date. Current Salesforce/Snowflake evidence is required for a live posture; Gong is needed only for call-derived quality judgments.

Reconcile created pipeline by source and rep, then inspect whether meetings show need/timing, usable context, a credible next conversation, stakeholder evidence, and clean AE handoff. Keep volume, conversion, data defects, rejected/returned meetings, and buyer quality distinct. Identify concentration, aging, single-thread risk, and the one intervention most likely to improve quality or creation.

Return a pipeline review with definitions, funnel snapshot, meeting-quality sample, source/rep patterns, data gaps, interventions, and commitments. State that no opportunity, attribution, forecast, or performance record was changed.

For behavioral validation, use [evaluation cases](references/evaluation-cases.md).
